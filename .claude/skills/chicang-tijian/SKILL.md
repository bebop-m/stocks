# 持仓体检

这个 skill 把 stocks.md 里已经定好的规矩，对着账本里的真实持仓算一遍，结果摆给用户看。只摆事实和算术，取舍由用户定（stocks.md 第 5 节），不说“过 / 不过”，不给买卖建议。规矩以 stocks.md 为准，这里只写怎么做；stocks.md 改了，这份跟着改。

三条底线，都来自用户（2026-11-21）：

- **不机械套框架。** 每家公司按它自己的生意看，不套同一张指标表、不按阈值自动下结论。例子：一家服装起家的控股公司，利润大头来自持有的金融股权，它不是服装股；它收到的分红记在投资现金流，用“自由现金流 ÷ 派息”看就会误判。所以脚本只做算术和规矩的状态，公司是什么、钱从哪来、该看哪个数，由你每次写进 notes.json。
- **数字要一眼有意义。** 用钱说话（万元）：一年到手多少股息，按持股比例你那份一年赚多少、欠多少、有多少。不用“X 倍”“市净率”这类数。比例只留规矩本身用的：息率对 5% 的锚，占比对 10%、20% 和一成线。
- **买入成本不看。** 那是沉没成本，拿不拿、加不加看现价买到的是什么公司（stocks.md 第 4 节）。只有管我财那条“仓位上限也按投入算”要用投入的钱，页面上也只显示据此算出的余量，不显示浮盈浮亏。

## 什么时候做

- **全面体检**：用户说体检一下、看看组合；业绩期、派息公告出来以后。做成 HTML 发给用户。每年两次业绩期以后（3、4 月和 8、9 月），打工仓每一只的派息都要核对，平时可以只核对有变化的。
- **买、加、换之前的单只检查**：不做全套，在对话里给一张七行的状态卡（见最后），再进入两块回答。

## 步骤

1. **读 stocks.md** 第 1、2、4、6 节（核心仓看第 3 节）：当年开支、核心仓买入上限、灰色地带、机会成本的基准。
2. **下载账本数据**到 scratchpad，不要放进 stocks 仓库（它是公开的）：

   ```
   gh api repos/<owner>/<账本私有仓库>/contents/data/portfolio.json -H "Accept: application/vnd.github.raw" > <scratchpad>/tijian/portfolio.json
   gh api repos/<owner>/<账本网页仓库>/contents/data/market.json -H "Accept: application/vnd.github.raw" > <scratchpad>/tijian/market.json
   gh api repos/<owner>/<账本网页仓库>/contents/data/fundamentals.json -H "Accept: application/vnd.github.raw" > <scratchpad>/tijian/fundamentals.json
   ```

   仓库名见 stocks.md 第 8 节。market.json 是账本网页用的行情（现价、过去 12 个月每股股息、派息历史），算出来的股息和账本对得上。fundamentals.json 只用来画每股收益走势和查财报币种。
3. **拉财报关键数**：把 `scripts/fetch_facts.mjs` 复制到 scratchpad，填上打工仓的代码和报告期，用 ego-browser 跑（taskSpace 用新的、说得清目的的名字，跑完 finish）。再整理：

   ```
   python -I .claude/skills/chicang-tijian/scripts/facts.py <原始文件目录> <scratchpad>/tijian/facts.json
   ```

   得到每家最近一个财年的净利润、派息、经营现金流、资本开支、投资收益到账，最近一期（港股只用年报和中报，季报的科目口径不稳）的现金、理财、有息借款、租赁、净资产、应收账款、预收款，和按 净利润 ÷ 每股收益 估的总股本。拉完对一眼借款：明显偏小的（比如有大额债券的公司只剩几十亿），回财报原文查。
4. **核对派息**（办法见下），结论写进 notes.json。
5. **写 notes.json**（格式见下）：每家公司的类型、行业、派息结论、特别股息、一句话，以及整个组合的几句复盘。
6. **跑脚本**（在仓库根目录）：

   ```
   python -I .claude/skills/chicang-tijian/scripts/checkup.py <portfolio.json> <market.json> \
       --fundamentals <fundamentals.json> --facts <facts.json> --notes <notes.json> [--costs <costs.json>] \
       --expense <当年开支> --reserve <备用金目标> [--margin-rate <融资年利率>] \
       --core-caps "<核心仓代码>=<上限>,..." --benchmark <基准代码> --bond-yield "<10 年期国债收益率>@<日期>" \
       --gray "<灰色地带代码>" \
       --groups "<组名>=<代码>,...;..." \
       --out <scratchpad>/tijian/checkup.md --html <scratchpad>/tijian/checkup.html
   ```

   - 参数里的数当次从 stocks.md 读，脚本里不写死。融资利率不知道就不传，页面会写“利率没给，不估利息”，不要自己猜。
   - `--bond-yield`：茅台自己的底线要和国债比（第 2 节）。东方财富接口 `RPTA_WEB_TREASURYYIELD` 的 `EMM00166466` 是中国 10 年期国债收益率，当次去查。
   - 过去 12 个月的股息，脚本按除净日自己算，正好满 12 个月那天的不算；账本有时会把那天的也算进去，两边不一样时，首屏会写出账本显示的数和差在哪一只。
   - `--groups`：会一起减派的放一组（都靠出口、都在地产链），可以跨行业，只用来做减派测试。
   - 底稿（--out）是给你看的，核对数字用，不要整份丢给用户。
7. **截图检查**：ego-browser 打开 HTML，设成 390px 宽，日间、夜间各截一次全页，看有没有横向溢出、文字重叠、数字对不上。
8. **交给 Gemini 挑错**（全面体检时）：把真实的体检文字版、底稿、notes.json 和 stocks.md 发给它，请它查算错的、和规矩对不上的、每家判断里不准或漏掉的事。它提到的外部事实回原文核对，对的改进去，不对的说明为什么不采纳。和它分歧的地方先在你们俩之间谈，真要用户取舍的才带给用户。
9. **发给用户**：SendUserFile 发 HTML；聊天里先用几行大白话说最要紧的事实（安全垫够不够、今年到现在、哪几只停手或过线、这次新发现的），最后只问一个问题。

## notes.json 怎么写

每家打工仓一项，键是代码；另有 `_summary`。示例（字段按需写，没有就不写）：

```json
{
  "_summary": ["今年到现在……", "融资……", "派息……"],
  "<代码>": {
    "type": "类型标签，8 个字以内",
    "industry": "行业，按利润和风险真正来自哪里归",
    "industry_change": "和上次分得不一样时，写一句为什么",
    "status": "cut | mixed | ok",
    "periods": [["中期", "0.50 → 0.30 → 0.35 港元（2024–2026）"], ["末期", "…"]],
    "recover": "恢复要回到哪一期的多少",
    "div_cur": "HKD",
    "special_ps": 0.05,
    "special": {"judgment": "经常性 | 一次性 | 说不准", "reason": "依据"},
    "runrate_ps": 4.3, "runrate_note": "为什么和过去 12 个月不一样",
    "restore_ps": 0.52, "restore_note": "恢复到降之前，每股多少",
    "buyback": {"pct": 0.016, "note": "回购多少、是不是注销、股数实际少了多少"},
    "extra": {"label": "这家公司特有的数", "amount": 40570000000, "sub_label": "…", "sub_amount": 1192000000},
    "context": "公司自己怎么解释",
    "user_view": "用户说过的判断，照原意写",
    "note": "一句话，55 字以内",
    "next_check": "下次核对的公告"
  }
}
```

- **类型和行业**：看年报“主要业务”和利润构成，不按公司名字或交易所的分类。行业 20% 是硬上限，最怕想买时换个归类腾额度，所以默认沿用上次的分法，改了要写 industry_change。
- **status**：按下面的办法核对后写。cut = 常规派息降了、还没回到降之前的水平（stocks.md 第 4 节的“先停手”）；mixed = 有升有降（比如末期降、中期升，或常规降了但加派特别息后合计更高），把每一期摆出来，由用户判断算不算恢复；ok = 核过没降。用户觉得会恢复，不改 status：事先定规矩就是为了不靠临场判断。用户的判断写进 user_view，等公告出来再核。
- **special_ps**：过去 12 个月（按除净日）每股特别股息，原币。行情源常把特别股息并进常规、不标出来，要以核对结果为准；脚本用它从账本口径里扣出“去掉特别股息”的数。judgment 三选一，写清依据：连续几期都有、写进了派息政策、还是卖资产或亏损时用存量现金派的。
- **runrate_ps**：过去 12 个月的数会被派息时间点带偏（比如中期息已经批准、还没除息，或改了派息次数）时，写最近一个年度的常规派息。
- **buyback**：只算注销、让股数实际减少的；给员工持股的不算。pct 是一年回购注销占市值的比例。现金股息率才是打工仓的锚，回购单列，要不要算进锚由用户定。
- **extra**：这家公司最该看、四格里没有的那个数。amount 是公司层面的金额（财报币种），脚本按持股比例折成用户那份；物业公司常用 `"receivables": true`，看应收账款一年涨多少、和营收比。
- **note**：一句话，55 字以内，只说钱从哪来、看哪一两个数，不写买卖建议，不写散文。
- **_summary**：三四句，每句一个事实：钱是怎么变的，今年发生了哪些规矩上的事（减派、过线、融资变化），操作有没有按方案来（比如换仓是不是先卖后买）。规矩定下来之前的操作，说明当时还没有这条，不拿它去对。

## 体检看什么

脚本都会算，你要核对、并在聊天里讲清的是：

1. **安全垫**（第 1 节）：一年税后股息（账本口径，含特别）打八折够不够当年开支；去掉特别股息再算一次。两个结论不一样时点出来。知道融资利率时，把一年利息加到开支旁边对照；要不要把利息算进规矩，由用户定。
2. **今年至今**：账本的算法，资金收益 = 现在 − 年初 − 今年净存入（含股息和汇率），除以年初净值。账本是年中才开始记交易和出入金的那一年，按账本开始那天拆成两段，前一段写明“没有出入金记录，只能当估算”。历年的收益和归因看账本网页的年度回顾页，体检不另做。
3. **结构与融资**：核心仓、打工仓、灰色地带各占多少；核心仓对买入上限（是回报最高时的买入上限，不是持有上限）；基准现在的股息率，打工仓要明显高于它（第 2 节）。融资余额 90 天前、30 天前、现在；最近 30 天买进和卖出差多少，对照第 6 节“先卖后买”。账本现金是各账户合起来的数，港股成交后两天才交收；融资余额以券商为准。
4. **同一类风险一起减派**（第 1 节）：每组减四成、五成后剩多少，含和去掉特别股息各一次，和八折分开算。
5. **行业上限**：打工仓按市值，20%；投入都知道的行业，也按投入算。
6. **打工仓每只**（第 2、4 节）：
   - “你这一份”：公司数 × 持有股数 ÷ 总股本，换成人民币。四格固定：一年到手股息、一年赚多少（附前一年和自由现金流）、净现金或净负债、净资产。借款只算银行借款和债券，不含租赁和应付款；物业公司账上的现金有一部分是业主预交的钱，要在一句话里说。
   - 停手：status 是 cut 的。
   - 一成线：单只股息占全部持仓股息到一成，只拿不加。含和去掉特别股息各算一次，有一个到了就算到了。例外按第 4 节算：这一只彻底停派，剩下的股息打八折还够开支。
   - 仓位：单只市值 10%；管我财那条，投入的钱也不超过 10%（行业 20% 同理）。
   - 5% 的锚：常规税后股息率低于 5% 的标出来；有回购的，把回购单列在旁边。
   - 规则余量：按市值 10%、行业 20%、投入 10%、一成线（静态约数）各算一个额度，取最小的，写出是哪一条卡住的；停手或过线就是 0。名字叫“余量”，不叫“还能加多少”；组合有融资时，页面上会写“新买要先卖后买”。
7. **买入理由**：有记录的亮出来对照（第 6 节）；还没有的照实说没有（第 7 节“买入理由记在哪里”还没定）。

## 管我财那条：按投入算的上限

- 来源：管我财的限制性仓位按买入价算，股价腰斩也不加，用来防系统性风险（2026-09-21，他说的是物业行业 20% 的上限）。用户 2026-11-21 采纳，写在 stocks.md 第 4 节。
- 投入 = 账本开始以后的买入，按实际花的钱算；卖出时按平均成本扣掉卖出那部分。账本开始以前就有的股数，要用户补投入的钱，存成 costs.json（`{"<代码>": 人民币金额}`），放 scratchpad 或用户指定的私有位置，不放 stocks 仓库。
- 没补的，照实写“账本开始前的成本没补，管我财那条先不算”。不要拿账本开始那天的市值代替：跌下来之前投进去的钱会算少，正好让这条失效。

## 页面（视觉规格，2026-11-21 和 Gemini 定的）

- 用账本 App 的禅意UI token（素禅日间、墨禅夜间，跟系统切换），另加 `--ink-2` 写次要文字，保证在手机上看得清：正文 14px，最小 12px，数字一律用 `--ink`。
- 分区靠留白和一根 1px 的发丝线，不画卡片框和阴影。进度线 2px，端点 7px 圆点。
- 状态只用两种点：朱色 = 规矩上的硬状态（停手、过一成线、市值到 10%）；金色 = 要留意（接近一成线、有升有降、常规息低于 5%、派息待核对）。没问题的不打标。盈亏按账本的红涨绿跌。
- 顺序：安全垫（首屏，不放盈亏）→ 今年至今和复盘 → 结构与融资 → 同一类风险和行业 → 打工仓每只 → 规矩上没问题的折叠成账单。
- 打工仓分三档：停手、过一成线、接近一成线或市值近上限的，整张展开；只是要留意的（有升有降、常规息低于 5%），只露抬头、状态、一句话和一年到手，其余收起；规矩上没问题的折成按行的账单。
- 每只打工仓：抬头（名字、类型、持仓、占净值）→ 状态（只写结论）、恢复要回到多少、规则余量（一成线的余量是静态约数，两种口径都写）→ 四格 → 一句话 → 例外、特有的数、恢复、特别股息、回购、用户的判断、行业变更、应收和预收 → 其余（派息记录、公司说、下次核对）折叠。
- 短缺、融资这类状态用正文色加一个朱点，不用红字：红绿只留给盈亏（红涨绿跌）。“成本没补”只在打工仓开头说一次。
- 要改页面，改 `scripts/checkup.py` 里的模板，不要在生成的 HTML 上手改。

## 核对派息的办法

- **港股**：etnet 派息页，按财政年度列出每一期（中期息、末期息、特別股息、不派中期息），连公布日期一起。ego-browser 打开 `https://www.etnet.com.hk/www/tc/stocks/realtime/quote_dividend.php?code=<去掉前导 0 的代码>`；load 事件常等不到，`goto` 超时不用管，等几秒直接读页面文字，从“公布日期”读到“備註：”。
- **A 股**：东方财富分红送配，ego-browser 打开 `https://datacenter-web.eastmoney.com/api/data/v1/get?reportName=RPT_SHAREBONUS_DET&columns=ALL&filter=(SECURITY_CODE%3D%22<代码>%22)&sortColumns=REPORT_DATE&sortTypes=-1&pageSize=12`，按报告期列出每次方案和进度（董事会通过、股东大会通过、实施分配）。
- **公司为什么减派**：看业绩公告原文（港交所披露易、巨潮资讯），把公司自己的解释写进 context。
- 核对时注意：
  - 中期对中期、末期对末期，特别股息不算；公司改了派息次数（开始派中期、按季派），看全年常规合计。
  - 已经公布、还没除净的方案要算进去：宣布减派到真正除净常要两三个月，这段时间股价先跌，最容易想加仓。
  - 用宣派的原币比。很多中资港股按人民币宣派，行情源折成港元，汇率一变，港元数会假涨假跌。
  - 送转、拆股、合股以后，每股派息要按股本变化调整再比。

## 买、加、换之前的单只检查

在对话里直接给七行。这一只的派息当场按上面的办法查（只查一只几秒钟），财报关键数也当场拉。换仓时先把要卖的那只扣掉，再算买完的占比；新买的股票没有旧的买入理由，那一行写“新买”。

1. 钱从哪来：现在的现金或融资余额；换仓是不是先卖后买（第 6 节）。
2. 仓位：买完市值占多少、投入占多少（上限 10%），所在行业买完占多少（上限 20%）。
3. 按现价买到的是什么：你这一份一年赚多少、分多少，净现金或净负债多少，净资产多少。
4. 一成线：买完股息占全部多少（含和去掉特别股息）；常规税后股息率是不是在 5% 以上。
5. 派息：最近几期，有没有降、恢复了没有。
6. 同一类风险：买完以后，这一组一起减派五成，股息还够不够开支。
7. 买入理由：有记录就亮出来，没有就说没有。

只说事实和规矩处在什么状态，比如“股息占全部的 21%，过了一成线，按第 4 节只拿不加”；不说“建议卖出”。用户问要不要买卖，按两块回答走，不在体检里答。

## 数据要注意

- `holdings[].quantity` 是期初股数；现在的股数看 `dailySnapshots[-1].holdings[].shares`，脚本已经这样处理。
- facts.json 的金额是财报币种（港股多数是人民币），脚本按 fundamentals.json 的 statementCurrency 换算；拿不准就在 notes 里写 `stmt_cur`。总股本是 净利润 ÷ 每股收益 估的，A+H 两地上市的公司已包含两地股数。
- 汇率用行情文件里的。
- 美股存托凭证的股数口径和股价对不上，“你这一份”会算错，这类公司要另外核对。

## 隐私

- 账本、行情、财报数据、notes、costs、体检报告都放 scratchpad，不写进 stocks 仓库（它是公开的）。这个 skill 的文件也在公开仓库里，不写任何持仓、金额或代码清单。
- Gemini 是用户请的顾问。和它讨论体检时，给真实的方案、持仓和体检结果，不要编样例数据（用户 2026-11-21：“不要虚构，Gemini是重要的顾问”）；只去掉它用不上的标识，比如邮箱、账户名、仓库地址。它说的事实和数字，核对原文后再用。别的外部服务不发。
